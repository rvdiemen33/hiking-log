# Backend persistence pattern (Domain + Infrastructure)

One `DbContext` for the whole application (`HikingLogDbContext`, SQL Server via EF Core 10, Code First).
Entities live in `HikingLog.Domain`; everything EF-specific lives in `HikingLog.Infrastructure`.

```
Domain/
├── Entities/<Entity>.cs                 ← plain classes, navigation properties on BOTH sides
└── Enums/<Enum>.cs                      ← e.g. Difficulty
Infrastructure/
├── Data/HikingLogDbContext.cs           ← DbSet<T> per entity (expression-bodied) + OnModelCreating
├── Data/Configurations/<Entity>Configuration.cs   ← IEntityTypeConfiguration<T>, registered explicitly
├── Data/DataSeeder.cs + SeedData.cs     ← Development seed (3 routes with ≥5 stages each)
├── Extensions/ServiceCollectionExtensions.cs      ← AddInfrastructure(): DbContext + IHikingLogDataContext
└── Migrations/                          ← generated by `dotnet ef`; never hand-edited
```

## Domain entities

- `HikingLog.Domain` references **nothing** — no EF Core, no data annotations, no Application types.
- `public class <Entity>` with an `int Id` primary key and `{ get; set; }` properties. Required strings
  initialise to `string.Empty`; optional ones are `string?`. Child entities carry the FK (`int RouteId`) **and**
  the parent navigation (`public Route Route { get; init; } = null!;`); parents expose the collection
  (`public ICollection<Stage> Stages { get; init; } = [];`).
- Enums get their own file under `Enums/`; dates without a time component use `DateOnly`.
- Every type and member has an XML `<summary>` (see `CLAUDE.md`).

## DbContext and the data-context interface

- `HikingLogDbContext` implements `IHikingLogDataContext` (defined in `HikingLog.Application/Data/Contracts/`).
  Every `DbSet<T>` appears on **both**; the interface additionally exposes `SaveChangesAsync`.
- DbSets are expression-bodied: `public DbSet<Route> Routes => Set<Route>();` (matches
  `csharp_style_expression_bodied_properties` in `.editorconfig`).
- `OnModelCreating` registers each configuration explicitly —
  `modelBuilder.ApplyConfiguration(new RouteConfiguration());` — no `ApplyConfigurationsFromAssembly`.
- Adding an entity is an **additive** edit to the context, the interface and `OnModelCreating`. Never regenerate
  these files from a snippet; you would clobber the other entities' registrations.

## Fluent API configurations

`internal sealed class <Entity>Configuration : IEntityTypeConfiguration<T>` in `Data/Configurations/`:

- `HasKey(x => x.Id)`.
- `HasMaxLength(n)` on **every** string column, `IsRequired()` for the non-nullable ones. Keep `n` in sync with
  the command validator's `MaximumLength(n)`.
- `HasPrecision(precision, scale)` on **every** `decimal`: `HasPrecision(8, 2)` for distances in km,
  `HasPrecision(8, 1)` for elevation in metres. Never `HasColumnType("decimal(...)")`.
- Enums are stored as strings: `HasConversion<string>().HasMaxLength(20)`.
- **Each relationship is configured exactly once, on the parent ("one") side**:
  `builder.HasMany(r => r.Stages).WithOne(s => s.Route).HasForeignKey(s => s.RouteId).OnDelete(DeleteBehavior.Cascade);`
  lives in `RouteConfiguration`; `StageConfiguration` owns Stage → HikeLog the same way. The child configuration
  never repeats it.
- No soft delete, no audit columns, no schemas, no case-insensitive column types — this project has none of those
  conventions; do not introduce them without an explicit request.

## Migrations

- Add migrations only through the `dotnet-ef-migration` skill:
  `dotnet ef migrations add <Name> --project src/HikingLog.Infrastructure --startup-project src/HikingLog.Api`,
  after `dotnet build` is green.
- Names are PascalCase noun phrases describing the schema change (`AddRouteTable`, `AddWeatherToHikeLog`); EF
  prefixes the timestamp. Never edit a generated migration by hand — remove it (only if unapplied) and regenerate.
- The API applies pending migrations at startup (`Database.MigrateAsync()`); the integration-test factory does the
  same against its Testcontainers SQL Server.

## Seed data

`DataSeeder.SeedAsync(app.Services)` runs in Development only and is guarded by a table-level `Routes.AnyAsync()`
check (it seeds only an empty database). The fixed records live in `SeedData.cs` — Noordzeepad (LAW 1),
Pieterpad (LAW 9) and GR 5, see `functional-plan.md`. Extend `SeedData` rather than adding inserts elsewhere;
`tests/HikingLog.IntegrationTests/Seeding/DataSeederTests.cs` covers it.
